# ROKA B2B CRM — MVP

**Не хочешь трогать терминал вообще?** Смотри `DEPLOY.md` — там инструкция,
как получить постоянную ссылку на приложение (открывается как обычный сайт),
всё делается кликами в браузере. Этот README — вариант для запуска на своём
компьютере через терминал.

Минимальное приложение для автоматизации B2B-продаж ROKA:
база клиентов + оценка fit/not fit + генерация писем на французском (через Claude) + релансы + дашборд.

Стек: **Streamlit** (интерфейс) + **Google Sheets** (база данных) + **Claude API** (тексты писем).
Без базы данных, без бэкенда, без деплоя — запускается на твоём компьютере одной командой.

---

## Как это устроено

```
roka_b2b_mvp/
├── app.py          — весь интерфейс (5 вкладок), запускается через streamlit
├── config.py       — ВСЕ настройки: статусы, секторы, веса скоринга, тон писем
├── sheets.py       — чтение/запись в Google Sheets
├── scoring.py      — расчёт fit-скора (правила, без AI — прозрачно и бесплатно)
├── letters.py      — генерация писем через Claude API
├── requirements.txt
├── .env.example    — шаблон настроек, скопировать в .env
└── .gitignore
```

**Логика воронки:**

`Nouveau → À qualifier → À contacter → Contacté → Relance envoyée → Répondu → RDV / Échantillons → Client`
(плюс тупиковые статусы `Non pertinent` и `Pas intéressé`)

1. Добавляешь клиента (вкладка **Clients**) — вручную, по одному. Заполняешь сектор, город, потенциал объёма, ощущение по чувствительности к цене.
2. Считаешь **Scoring** — балл 0–100 по прозрачным правилам (не AI). Клиент с высоким баллом сам переходит в статус "À contacter", с низким — в "Non pertinent".
3. На вкладке **Lettres** для клиентов "À contacter" жмёшь "Générer la lettre" — Claude пишет персональное письмо на французском под этого конкретного клиента. Читаешь, правишь, жмёшь "Ouvrir dans mon client mail" (откроется черновик в твоей обычной почте) и отправляешь сам. Отмечаешь "Marqué comme envoyé" — статус меняется, дата следующего реланса ставится автоматически (+4 дня, настраивается).
4. Вкладка **Relances** каждый день показывает, кого пора релансить (прошло 4 дня без ответа). Аналогично — генерируешь текст, отправляешь сам, отмечаешь.
5. **Dashboard** — сколько клиентов всего, сколько fit, конверсия в ответ, кого релансить сегодня.

**Письма никогда не отправляются автоматически.** Приложение только готовит текст и открывает его в твоём почтовом клиенте — ты сам решаешь, отправлять или нет. Это осознанный выбор для MVP: без риска случайной рассылки и без настройки почтового API.

## Установка (пошагово)

Нужно один раз настроить: Python-окружение, доступ к Google Sheets, ключ Claude API.

### Шаг 0. Python

Нужен Python 3.10+. Проверить: `python3 --version`.

```bash
cd roka_b2b_mvp
python3 -m venv venv
source venv/bin/activate      # на Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Шаг 1. Создать Google-таблицу

1. Зайди на [sheets.google.com](https://sheets.google.com) и создай новую таблицу.
2. Назови её ровно так же, как будет указано в `.env` (по умолчанию `ROKA B2B CRM`).
3. Больше ничего делать в таблице не нужно — лист "Clients" и заголовки колонок приложение создаст само при первом запуске.

### Шаг 2. Создать сервис-аккаунт Google (чтобы приложение могло писать в таблицу)

1. Открой [Google Cloud Console](https://console.cloud.google.com/).
2. Создай новый проект (или используй существующий).
3. В меню слева: **APIs & Services → Library** — включи два API:
   - **Google Sheets API**
   - **Google Drive API**
4. **APIs & Services → Credentials → Create Credentials → Service Account**. Дай любое имя, например `roka-crm-bot`.
5. Открой созданный сервис-аккаунт → вкладка **Keys → Add Key → Create new key → JSON**. Скачается файл — переименуй его в `credentials.json` и положи в папку `roka_b2b_mvp/` (рядом с `app.py`).
6. В файле `credentials.json` найди поле `client_email` (выглядит как `roka-crm-bot@...gserviceaccount.com`).
7. Вернись в свою Google-таблицу → кнопка **Share (Поделиться)** → вставь этот email → дай права **Editor (Редактор)**.

Без этого шага (7) приложение не сможет читать/писать в таблицу — самая частая ошибка.

### Шаг 3. Получить ключ Claude API

1. Зайди на [console.anthropic.com](https://console.anthropic.com/), создай API-ключ.
2. Понадобится для генерации писем (шаг 5 ниже).

### Шаг 4. Настроить .env

```bash
cp .env.example .env
```

Открой `.env` и заполни:
- `ANTHROPIC_API_KEY` — ключ из шага 3
- `GOOGLE_SHEET_NAME` — точное название таблицы из шага 1
- `SENDER_NAME`, `SENDER_ROLE`, `SENDER_EMAIL` — как подписывать письма

### Шаг 5. Запуск

```bash
streamlit run app.py
```

Откроется браузер на `http://localhost:8501`. Готово.

## Как менять под себя

Всё, что можно захотеть поменять в первую очередь, — в **config.py**, без трогания остального кода:

- `STATUSES` — статусы воронки
- `SECTORS`, `SOURCES` — справочники
- `SECTOR_SCORE`, `REGION_SCORE`, `VOLUME_SCORE`, `PRICE_SENSITIVITY_SCORE`, `FIT_THRESHOLD_*` — веса скоринга
- `BRAND_CONTEXT` — описание бренда и тон, которое видит Claude при генерации писем
- `RELANCE_DELAY_DAYS` — через сколько дней релансить (сейчас 4)

Тексты промптов для писем — в `letters.py`, функции `generate_first_letter` и `generate_relance`.

## Ограничения этой версии (осознанно, чтобы не раздувать MVP)

- Один пользователь одновременно (Google Sheets как БД не любит гонки записи при 5+ одновременных пользователях — для одного менеджера продаж это не проблема).
- Добавление клиентов — только вручную через форму. Импорт из CSV/LinkedIn — следующий шаг, если MVP приживётся.
- Письма не отправляются автоматически — только черновик + "открыть в почте". Это защита от случайной рассылки, сделано намеренно.
- Скоринг — по явным правилам, не AI. Это сделано специально: скор должен быть объяснимым и не "плавать" от запроса к запросу.
- Реланс всего один по умолчанию (потом статус "Relance envoyée" — дальше решаешь вручную, повторной автоматической эскалации нет).
